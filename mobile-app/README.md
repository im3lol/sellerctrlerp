# SellerCtrl Mobile

تطبيق Android Native مستقل لـ SellerCtrl، مبني بـ Kotlin وJetpack Compose ومصمم أولًا للهاتف العربي (RTL).

## ما الذي يغطيه الآن؟

- الدخول الآمن إلى API الموبايل عبر Bearer token قصير العمر ومؤسسة المستخدم النشطة.
- مزامنة لحظية عبر SSE؛ أي تغيير في النظام يعيد تحميل البيانات المعروضة.
- لوحة رئيسية مهيأة للهاتف: مؤشرات، تنبيهات تجديد المخزون، إجراءات سريعة، وأقسام عملية.
- قارئ باركود بالكاميرا، الأصناف، الجرد والتسويات، التحويلات، الحزم، والتنبيهات.
- دورة المبيعات والمشتريات، العملاء والموردون، المحاسبة والبنوك، الموارد البشرية، والتقارير والقوائم المالية.
- الصلاحيات لا تُكرر داخل التطبيق: الخادم يطبق نفس صلاحيات ERP وعزل المؤسسة على كل طلب.

## تشغيل التطوير

يلزم JDK 17 وAndroid Studio. على Windows:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd mobile-app
.\gradlew.bat :app:assembleDebug
```

ملف APK التجريبي سيكون في:

`app/build/outputs/apk/debug/app-debug.apk`

## إعداد بيئة الـAPI

الإصدار الافتراضي يتصل عبر HTTPS بـ `https://www.sellerctrl.com/`.

لبناء نسخة مرتبطة ببيئة Staging، مرّر العنوان دون أي أسرار:

```powershell
.\gradlew.bat :app:assembleDebug -PMOBILE_API_BASE_URL=https://staging.example.com/
```

للعمل محليًا مع Docker عبر هاتف موصول USB، استخدم `adb reverse tcp:3001 tcp:3001` ثم مرّر `http://localhost:3001/` للتطوير فقط. لا يُستخدم HTTP في إصدار العميل.

## مبادئ UX

- أسفل الشاشة: الرئيسية، الأصناف، المسح، والمزيد؛ أهم المهام في متناول الإبهام.
- القائمة الكاملة تظهر من «المزيد» ولا تُحمّل المستخدم كل وحدات ERP دفعة واحدة.
- العربية وRTL هما الافتراضي، مع بطاقات قابلة للمس ومساحات واضحة.
- العمليات المالية والمخزنية تبقى على دورة المستندات نفسها في الخادم؛ التطبيق لا يتجاوز التأكيد أو الترحيل.
